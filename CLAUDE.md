# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

This repository builds a RAG (Retrieval Augmented Generation) tool that converts technical datasheets and technical manuals into markdown documents for efficient access. Truthfulness, accuracy and precision of information are paramount. No error is allowed; this is engineering documentation.

The tool is general. It must handle many publishers and document types (component datasheets, equipment datasheets, instruction manuals, service manuals). Every rule in `tools/` is a document-independent problem class with a detection criterion. No rule keyed to one publisher, font, layout or document. A study case (`sources/<case>/`) is evidence for a class, never the definition of it.

## Accuracy and sourcing — overrides every other rule

- Use only information found in this repository's files. No general knowledge, no typical values. Never infer or invent a tag, part number, rating, setpoint, procedure or cross-reference.
- Cite every factual entry to its source: extraction file name + section, table or row, carrying the drawing location the extraction itself cites (sheet, table, coordinate).
- Missing, ambiguous or conflicting information is stated as such, or requested from the user. Never resolved by a guess. Two extractions that disagree are reported as the disagreement, both citations given.
- Neutral technical prose. Short sentences, concrete words, tables over prose. No emojis.
- No documentation, summaries or logs unless asked.
- No history. Update a fact in place and delete the resolved item. A count written in prose goes stale; cite the command that prints it.

## Repository state

- Not a git repository. There is no commit history to consult or cite.
- No build system, linter or test suite. All tools are Python 3 standard library plus poppler-utils (`pdftotext`, `pdftohtml`, `pdffonts`, `pdfimages`, `pdftoppm`, `pdfinfo`) and `tesseract` 5 (eng); they run offline and deterministically. No API, no network, no Python package. The model in the loop (stage 3) is Claude in the Claude Code session, reading crops with the Read tool; `tools/review.py` prepares the items and validates what the session decided.
- `sources/<case>/` holds input documents (PDF, HTML). `extracted/<case>/<basename>.md` is the verbatim extraction of each source; `structured/<case>/<basename>.md` is the structured document built from it — the deliverable; `review/<case>/<basename>.md`, when present, is the session's stage 3 review that stage 2 applies. One file per source, paths mirrored. `ls -R sources extracted structured review` prints current contents.
- Two deterministic stages, on purpose: `extracted/` is never rewritten beyond page/figure markers, so every line of `structured/` can be checked against it; `tools/check.py` does that for every number. Stage 3 adds only flagged data on top: the reviewer never rewrites body text, a transcription is marked as from the page image and its numbers are counted apart (`model`), a table re-arrangement must keep every word (byte-identical) or is rejected, and a glyph reading is a candidate that goes into `tools/glyphs.txt` only by hand.
- OCR: stage 1 OCRs every figure region and every page without a text layer; the text is flagged `(tesseract, unverified)` and the marker carries the word statistics; stage 2 keeps it only above a confidence floor. An HTML source has no stage 2: `html_to_md.py` writes `extracted/` and the same file is copied to `structured/`.
- Evidence from the rendered page enters `extracted/` only as page notes (ligatures restored by OCR, list markers drawn but not in the text layer); stage 2 applies them. The body text of `extracted/` stays the text layer, verbatim.

## Tools

Run every command from the repository root: `check.py` without arguments globs `structured/**`, `survey.py` derives `extracted/…` from a `sources/…` path, and the data files are found next to the scripts. `extract_all.sh` changes to the root itself.

| Command | Does |
|---|---|
| `tools/extract_all.sh [--force]` | Runs both stages over `sources/`; skips up-to-date outputs unless `--force` |
| `python3 tools/pdf_to_md.py <in.pdf> <out.md>` | Stage 1: one PDF to verbatim text with markers (see below) |
| `python3 tools/structure.py <extracted.md> <in.pdf> <out.md> [<review.md>]` | Stage 2: headings (font size/bold), paragraphs, lists, tables, TOC and boilerplate removal, addenda section, sub/superscript notes; applies a review file when given |
| `python3 tools/review.py prepare <extracted.md> <in.pdf> <structured.md> <workdir> [--tasks figures,glyphs,tables] [--limit N]` | Stage 3, step 1: writes `items.md` (one block per item), contact sheets `sheet_NN.png` (crops stacked, a black band with k white squares above row k), single crops, and `review.md` with every item PENDING. Use a scratch directory as `workdir`; crops are never kept in the repository |
| `python3 tools/review.py validate <extracted.md> <in.pdf> <structured.md> <review.md>` | Stage 3, step 3: checks the edited review file — every item exists, nothing PENDING, a corrected figure has lines, a corrected table has exactly the original words (else rewritten as `rejected` with the difference). Exit 1 while problems remain. `<structured.md>` must be a stage 2 output built without the review (items are keyed by figure `(pdf page, N)` and table `(pdf page, first row)`, and an applied review changes a corrected table's first row). It rewrites the review file in place; a `corrected` table it cannot find is kept as a bare marker and its rows are lost, so keep a copy until it reports `problems 0` |
| `python3 tools/html_to_md.py <in.html> <out.md>` | One HTML document to markdown (headings, lists, tables, image markers) |
| `python3 tools/check.py [<extracted.md> <structured.md>]` | Faithfulness check: every numeric token in `structured/` must exist in `extracted/` (invented must be 0); tokens dropped by stage 2 are listed by page (contents pages, index pages, cover repeats and chapter numbers in running headers are the expected ones); tokens on pages with an omitted section are counted apart as `omitted`; numbers inside model transcriptions (stage 3) apart as `model`. Run it after any change to `structure.py` |
| `find sources -name '*.pdf' \| xargs -d '\n' python3 tools/survey.py` | One row per PDF: pages, text-less pages, image pages, layout classes, drawing pages, symbol/unknown/no-ToUnicode fonts |
| `python3 tools/figures.py <pdf> <page> ...` | Prints the figure regions the extractor would mark on those pages |

Data files read by stage 2, next to the scripts: `tools/glyphs.txt` (font family + glyph → replacement, each line verified against the rendered page and citing where; an optional last column restricts a line to one source file), `tools/omit_sections.txt` (titles of legal, warranty, trademark and regulatory sections left out of `structured/`; `*` wildcards; matched against the whole normalised heading), `tools/boilerplate.txt` (phrases that drop a line).

Every tesseract call runs on one thread (`OMP_THREAD_LIMIT=1`) with a time limit; several multi-threaded tesseracts side by side spin-wait each other to a crawl (a 2 s page took 7 min). Parallelise over documents, not inside one.

`extract_all.sh` gotchas: it compares source and output modification times only (and a review file newer than the structured file), so editing a tool does not trigger re-extraction; use `--force` after a tool change, or loop `structure.py` over the corpus after a stage-2-only change. It runs the Python tools with stderr discarded; on a `FAIL` line, run the single-file command by hand to see the traceback.

## Conversion procedure

When the user puts a document under `sources/<case>/` and asks for a conversion, run these steps in the session and hand over `structured/<case>/<name>.md`:

1. `tools/extract_all.sh` — stages 1 and 2 for every new or changed source (a 100-page manual with OCR takes a few minutes; run it in the background and wait for it).
2. `python3 tools/review.py prepare extracted/… sources/… structured/… <scratch>/<name>` — the work items. `items.md` says what each is; `--tasks` and `--limit` narrow a long document.
3. Read the sheets (`sheet_NN.png`) with the Read tool; open a single crop (`fig_pP_N.png`, `table_pP_K.png`) or render a zoom with `pdftoppm -r 400 -x … -y … -W … -H …` when a detail is not certain. Edit `review.md` in the scratch directory, replacing each PENDING:
   - figure: `verified` only when every tesseract line is exactly right and complete; `corrected` followed by the transcription lines and `<!-- end of reviewed figure N -->`, one line per printed line, exactly as printed, `?` for a character that cannot be read, nothing added or expanded; `no_text` when the only text in the region is already in the text layer (say so in the note); `illegible` when text exists but cannot be read.
   - table: `matches`; `corrected` followed by the markdown table and `<!-- end of reviewed table -->`; `not_a_table` (stage 2 split running text or a list into a table); `unreadable` (the crop cannot be read). Only lines starting with `|` are read back and the separator row is ignored. Move, split, merge cells, add empty cells; never retype a cell — copy its text, or build the rows by script from the original cells (a Greek Ω typed for an Ohm sign Ω is a rejected table). Put a spanning row's text in its first cell; a spanning header text that is not in the markdown cannot be added.
   - glyph: the printed glyph, its name, confidence; it is not applied — verify and add a line to `tools/glyphs.txt`.
4. `python3 tools/review.py validate …` until it reports `problems 0`, passing the `structured/` file from step 1 (no review applied yet). Copy the review file to `review/<case>/<name>.md`. Once stage 2 has applied it, `structured/` no longer matches the review's table keys; for a later `prepare` or `validate` run, build a no-review file first: `python3 tools/structure.py extracted/… sources/… <scratch>/noreview.md`.
5. `tools/extract_all.sh` (stage 2 sees the review file) and `python3 tools/check.py extracted/… structured/…`: `invented 0`; `model N` is the count of numbers taken from the page image, each inside a block marked `review: text from the page image, unverified by a person`.
6. Report: what was reviewed, what was corrected, what stayed unverified (`illegible`, values a person must read), and the check line. Scratch crops are deleted; the repository keeps only the three markdown files per source.

Work items and what is accepted, all validated in code before stage 2 sees them:

- Figures: every region whose OCR saw words (kept or below floor); a region with no OCR words at all (photo, logo) is not an item unless the reviewer opens it. A corrected transcription reaches `structured/` under its figure marker with `review: text from the page image, unverified by a person`; `check.py` then skips tesseract's superseded block and counts the transcription's numbers as `model`.
- Tables: every markdown table, located on the page by its words (whole page when fewer than 60 % are found). Accepted only when the multiset of words equals the original cells'; the accepted rows replace the table in `structured/` under a `table re-arranged …` marker.
- What stage 3 leaves in `structured/`, greppable: a figure marker gains `| review: text from the page image, unverified by a person …` (corrected, transcription follows), `| review: tesseract reading verified against the page image …` (verified) or `| review: no_text|illegible on the page image …` (the OCR block is dropped); a re-arranged table sits under `<!-- table re-arranged to the printed layout from the page image (note); words unchanged -->`. Glyph candidates leave nothing.
- Glyphs: every flagged-font glyph with no line in `glyphs.txt`, one occurrence cropped with context; written as `glyph candidate`, never applied by code.
- Sheets are rendered at 130 dpi (width ≤ 1000 px, height ≤ 1500 px), single crops at 200 dpi (long side ≤ 1568 px).

`pdf_to_md.py` output, in order: a font-check block, then one block per page. Everything is verbatim text layer; nothing is corrected.

- `<!-- font check: <family> is not a standard text face; glyphs "…" on pages … -->` — those glyphs are unreliable until verified against the rendered page (`pdftoppm -png -r 110 -f N -l N`); a verified meaning goes into `tools/glyphs.txt`, never into the code. A `no ToUnicode map` line means ligatures (fi, fl) or special glyphs may be missing; it names the pages stage 1 OCR'd to check.
- `<!-- ligatures: … words restored from the rendered page (tesseract, confidence >= 80): lux->flux, … -->` — page note; the OCR reading of the word is the text-layer word with an `f` inserted before i, l or f and nothing else, so it is accepted as the dropped fi/fl/ff glyph. Stage 2 replaces the whole word on that page.
- `<!-- list markers drawn on the page, not in the text layer (from the rendered page): "line start" | … -->` — page note; a small isolated ink mark left of the line, outside every text box and figure, with no text further left on the row and no counterpart right of the line. Stage 2 prefixes the line with a bullet.
- `<!-- pdf page N | printed page L | header: … | footer: … -->` — cite by `pdf page N`. Running headers/footers are removed from the body and kept here; the header usually names the chapter.
- `<!-- drawing page: … -->` — the page text is figure labels only.
- `<!-- figure N on pdf page P at x0,y0-x1,y1 pt | caption: … | text-layer labels: … | OCR … -->` — a raster or vector graphic, referenced by page and position so it can be found in the source. `caption:` is asserted only for a "Figure N"-style block; otherwise the nearest centred text below is reported as such. `text-layer labels` are short text blocks inside the region, `nearby labels` short blocks within 40 pt of it (callouts, dimensions); stage 2 leaves such label-only blocks out of the body text. The OCR text follows the marker up to `<!-- end of figure N -->`, flagged `unverified; K/N words >= 60, mean confidence M` (words seen by tesseract, words kept, mean over all); an OCR word lying on a text-layer word box is the text layer seen again (a shaded box or icon region overlapping a paragraph) and is left out before the statistics. Figures are never described or saved as images. A page without a text layer is OCR'd whole.
- Two-column pages are read column by column; a full-width table is kept whole. Bands that look like a table are never split (an interleaved column is readable, a cut table is not).

`structure.py` rules: heading levels come from font sizes used on more than one page (a cover title sets none); a header change between pages opens a `##` chapter when the body has no such heading; a bold line whose next line starts lowercase is a paragraph lead-in, not a heading; a publisher's marker glyph in front of a heading (◇, ■, ❍) is stripped from the heading text. The document title is the PDF metadata title unless it looks like a file name, else the largest text on page 1. Glyphs of a flagged font are replaced from `tools/glyphs.txt` in body and headings; a run of one glyph (Icom draws a pictogram as a wide and a thin glyph, `qq`) is one glyph; circled step numbers ①…⓴ are list markers. Dropped text: contents lines (dot leaders or "— page N"), lines in text blocks (not table rows) holding a phrase from `tools/boilerplate.txt` (marketing and legal wording only), OCR text of a figure below the floor (marker says `OCR below floor, text not used`), and sections whose heading is a title in `tools/omit_sections.txt` — the heading's own body up to the next heading of any level, replaced by `<!-- omitted: "title" (pdf pages a-b; n lines) … -->`; a container heading with no body of its own stays and its sub-sections are judged by their own titles. Nothing else is removed or reworded.

## How the stages work

Read this before changing a threshold; every constant applies to every document.

- Stage 1 geometry: one `pdftotext -bbox-layout` pass gives every text block's box. Per page, blocks are classed left, right or full-width relative to the page midline (`TOL` pt); full-width blocks cut the page into horizontal bands, and each band is re-extracted with `pdftotext -layout` on a crop box (two crops for a two-column band). A band stays full-width when its gutter is narrower than `MIN_GUTTER` or its left and right single-line blocks share baselines (`table_rows`). Page furniture is an outermost top- or bottom-zone block whose text (digits wildcarded) repeats on `REPEATS` pages; it is cropped out and its text goes to the page marker.
- Figures (`figures.py`): the page is rendered grey at `DPI` 30, text blocks are masked, edge pixels form connected components, overlapping boxes merge. A box is a table, not a figure, when it holds `TABLE_BLOCKS` column-aligned text blocks or its inside blocks share baselines with longer text outside. Regions are OCR'd at `OCR_DPI` 300; words under confidence `OCR_CONF` are dropped.
- Stage 2 re-reads the PDF with `pdftohtml -xml` for font size, bold and font family; the extraction carries no font information. Heading candidates found in the XML are matched back to body lines (up to three consecutive lines) by normalised text (`norm`), so a heading whose text differs between the two poppler outputs is not recognised. Sub/superscript pairs come from the same XML. Glyph replacement is located the same way: each XML row holding a flagged-font fragment becomes a regex (glyph runs as groups, neighbouring words as context) applied to that page's body lines; a row of glyphs alone must match a whole line, or a lone `t` callout would rewrite every `t` on the page.
- Ligature check (stage 1): on a page that uses a font without a ToUnicode map, the page is OCR'd at 300 dpi in sparse-text mode and each text-layer word is matched to the OCR word under its box; the only accepted difference is an inserted `f` before i, l or f at confidence ≥ 80, and never when another reading of the same word equals the text layer. In this corpus the loss occurs in one datasheet (Myriad Pro); most no-ToUnicode subsets carry no ligature glyph.
- Drawn list markers (stage 1): 72 dpi grey render, all text-layer words masked, strip of 16 pt left of each line start; the component found there is flood-filled without a vertical bound, and only a single component no larger than `MARK_SIZE` (0.75) of the line height, not reaching the strip's left edge, with no text-layer word further left on the row and no ink in the mirror strip right of the line, counts. Hatched note bars, dashed box borders, circled callouts and inline icons all fail one of those.
- Stage 2 tables: a column cut is a character range blank in 90 % of the rows that have text on both sides of it; a cut that falls inside text (a spanning cell) is skipped for that row, so later columns keep their index. A table span that does not yield at least two rows and two columns is kept as a fenced block with its alignment intact.
- `check.py` ignores comment markers but counts the labels listed in figure markers as present on both sides; OCR text is compared like body text. A paragraph joined across a page break moves its tokens by one page.
- Thresholds are named constants at the top of each tool (`TOL`, `SPAN_SHARE`, `MIN_GUTTER`, `TABLE_SHARE`, `SPARSE`, `TOP_ZONE`, `BOTTOM_ZONE`, `REPEATS`, `OCR_CONF`, `OCR_TIMEOUT`, `LIG_CONF`, `MARK_REACH`, `MARK_SIZE` in `pdf_to_md.py`; `HEAD_BIG`, `HEAD_MAXLEN`, `OCR_SHARE`, `OCR_MEAN` in `structure.py`; `EDGE`, `MIN_SIDE`, `MIN_DENSITY`, `TABLE_BLOCKS`, `ROW_SHARE`, `MAX_LABEL`, `NEAR` in `figures.py`; `CROP_DPI`, `SHEET_DPI`, `SHEET_W`, `SHEET_H` in `review.py`). After changing one, run `tools/extract_all.sh --force` and `python3 tools/check.py`, and diff outputs across several cases, not one. The OCR floor was set from the corpus distribution of per-figure statistics (share of words kept, mean confidence): below 0.4 / 45 the text is callout digits, pixel fonts or texture; above it is mostly labels, but LCD pixel-font screenshots still pass with plausible wrong words, which only a person can catch.

## Known limits

Extractor: three or more columns are not split. The column gutter is assumed near the page midline; with a wide and a narrow column the wide column's blocks straddle the midline, the band is read as one flow, and stage 2 then splits the interleaved lines into a table. Two independent tables side by side come out row-interleaved (split them at the wide gap). A PDF page that holds two printed pages side by side (2-up spread) is read left page then right page but gets only one printed-page label. Sub- and superscripts are flattened (V_DD reads as VDD). A ligature dropped by a font without a ToUnicode map is restored only where OCR reads the word at confidence 80 or more; in running headers and footers (page markers) it stays dropped. Formulas laid out in two dimensions come out scrambled; the pieces of a tall bracket are mapped to one bracket on the equation line. Chapters shorter than three pages keep their running header in the body. Merged table cells appear on one of their rows only. A list marker that is neither a text-layer glyph nor an isolated drawn mark (an icon with several parts, a marker touching a rule) is not recovered.

OCR (seen in this corpus): LCD pixel fonts produce plausible wrong words (`Hext TX atter`, `POLLIMS`) at confidences that pass the floor; the text is flagged unverified and needs a person or stage 3. Tick marks are lost, coloured callout digits in drawings read as `1?`, `2?` and are removed by the floor.

Stage 3: a session transcription is as unverifiable as OCR — it is flagged, counted apart, and a person signs off on any value taken from it. Table location by words fails on tables whose cells are mostly one-character tokens (the whole page is cropped instead). Headings are not reviewed. Reviewing is session work: a datasheet takes minutes, a 100-page manual with 200 figures and 60 tables is hours of reading; `--tasks` and `--limit` split it. A rotated or very small marking on a drawing is left out and said so in the note.

Structuring: tables are split on column gaps of two or more spaces; a table whose columns are one space apart stays partly merged, and header rows that span several columns land in one cell. Bold labels at a margin ("White: Talker A") become low-level headings. Sub/superscripts are recovered only where the small span is a separate text fragment. A glyph of a flagged font with no line in `tools/glyphs.txt` stays as the text layer gives it; the font check block names it. An omitted section's page note and page markers are kept, its figures are not.
